Управление инцидентами

Инциденты классифицируются как P1, P2 и P3.

P1 — критический инцидент.

К P1 относится полная недоступность ключевой системы, блокировка биллинга либо нарушение работы более чем для 30% активных пользователей.

О P1 дежурный инженер должен быть уведомлён не позднее пяти минут после подтверждения инцидента.

Incident manager должен быть уведомлён не позднее десяти минут после подтверждения P1.

Для P1 обязательно создаётся отдельная war room.

Обновление статуса P1 публикуется каждые 20 минут до восстановления сервиса или изменения классификации.

P2 — существенная деградация, затрагивающая от 10% до 30% пользователей, либо проблема с доступным временным обходным решением.

P2 должен быть зарегистрирован не позднее 15 минут после подтверждения.

Для P2 war room создаётся по решению incident manager.

Статус P2 обновляется не реже одного раза в 60 минут.

Если инцидент влияет на внешних клиентов, уведомление клиентской поддержки организует incident manager.

Дежурный инженер не должен самостоятельно отправлять массовые сообщения клиентам.

После восстановления выполняется разбор причин.

Postmortem для P1 должен быть подготовлен в течение двух рабочих дней.

Postmortem для P2 должен быть подготовлен в течение пяти рабочих дней.

Для P3 обязательный postmortem не требуется.

При изменении масштаба воздействия incident manager может изменить классификацию инцидента.

Таймеры дальнейших уведомлений отсчитываются уже по правилам новой категории.
